# Q0 快問 + 六類決策問題的個別處理流程

Q1–Q6 共用主流程(SKILL.md Step 1–6),本文件只寫差異點,
輸出格式見 report-templates.md;Q0 快問是唯一**不產報告**的模式,
規則全部寫在本節。

## Q0 快問(純提問;「支撐在哪」「外資買嗎」「上次怎麼說」)

**定位:資訊問題,不是決策問題。**照樣跑腳本拿新鮮數據、照樣引過往決策,
但直接在對話中回答——不產報告、不存檔、不記預測、不記事件。

### 分類判準

- **進 Q0**:問數據事實(價位/指標/籌碼/營收/配息日期)、問狀態
  (「上次的預測現在怎樣了」)、問解釋(「為什麼上次叫我等」)、
  問系統紀錄(歷史報告/預測/事件)
- **不進 Q0(走 Q1–Q6)**:問句含「能不能買/賣」「該不該」「怎麼操作」
  「點位建議」「推薦」「配置」,或任何回答等同於給出新的買賣建議的問題
- **模糊 → 預設 Q0**,回答結尾附「需要完整決策報告嗎?」
- **升級條款**:快問回答後使用者追問到決策(「所以能買嗎」)→
  升級走完整流程;Q0 已抓的資料直接沿用,不重抓

### 按需抓取(只跑問題需要的,不跑標配全套)

| 問題在問 | 跑什麼 |
|---------|--------|
| 價位、支撐壓力、趨勢、指標 | `fetch_ohlcv`(增量)→ `compute_ta`;要現價 → WebSearch 標時間戳 |
| 法人、融資券 | `fetch_chips` |
| 營收、公告 | `fetch_mops` |
| 過往決策、表現、「上次怎麼說」 | `recall_history`;要最新判定 → `verify_predictions --fetch` |
| 新聞、最近消息 | `cache_news --recall` → 不足再 WebSearch(**現抓仍要 `--save` 回寫**) |
| 除息、法說等關鍵日期 | `log_events --show --symbol` → 缺再 WebSearch |

### 回答紀律

1. **資料紀律與完整流程完全相同**:技術指標只能引 compute_ta 輸出、
   籌碼只能引 fetch_chips,禁止目測/心算/憑印象;每個數字標來源與時間。
   現價可單一來源(快問只陳述事實,標注即可;雙來源是評分紀律)
2. **觀點只能轉述,禁止新產**:可以引用最近報告的結論
   (「7/15 給中性 47,目前 PENDING,失效條件未觸發」),
   **不得產生新評分、新方向判斷、新進出場點位**——那些是完整流程
   (多空對辯+rubric)的專屬產出,快問給了就是繞過紀律的後門
3. 舊觀點與新數據明顯衝突時(如失效條件已觸發)→ 照實陳述衝突,
   並建議跑一份完整報告,自己不下新結論
4. 回答結尾附一句非投資建議聲明(一句即可,不用完整風險段落)

- 側重:技術面 + 消息面;時框:1d 為主、1w 確認大方向(加密貨幣加 4h)
- **必附交易計畫表**:進場區間 / SL / TP1 / TP2 / R:R,全部錨定
  compute_ta 的支撐壓力與 ATR(規則見 scoring-rubric.md §V)
- R:R < 1.5 → 結論寫「建議等待」,並給出「等到什麼價位/條件才值得進」
- horizon_days = 14(波段)或 30(順勢),在 prediction-meta 中記錄

## Q2 長期持有判斷(「X 能長抱嗎」)

- 側重:基本面 + 護城河;消息面只看結構性事件(監管、產業變局)
- 必答三個問題:
  1. 6 個月與 12 個月的多頭論點各是什麼(分開陳述)
  2. 論點依賴哪些假設(成長率、市占、政策)
  3. **失效條件**:哪些可觀察事件發生時應該離場(可證偽、具體)
- 不給短線進場價,但給「合理估值區間」與「目前價位在區間的位置」;
  掛單表(必附,見 report-templates.md「掛單表區塊」)以估值區間下緣
  作為長期分批的被動限價錨,不是短線交易計畫
- direction 通常 long/neutral,無交易計畫欄位;horizon_days = 180

## Q3 標的推薦(Screener Mode)

篩選漏斗:

```
市場掃描(新聞熱點 / 板塊資金流 / 漲幅榜)→ 初選 8–12 檔
  → 輕量評分(僅消息面+技術面,每檔 ≤ 2 次搜尋)→ 淘汰至 3–5 檔
  → 存活者做完整四維度評分(權重用 Q3 欄,技術面 45%)
  → 排序表 + 每檔一段論述 + 進場參考位
```

- 推薦表**必須含「主要風險」欄**,禁止只列多頭理由
- 長期推薦改用該資產類別的標準權重(非 Q3 欄)
- **每一檔各記一筆預測日誌**(question_type = Q3_screener),
  短期 horizon 14 天、長期 90 天
- **淘汰者也要留反事實紀錄**:輕量評分後被淘汰的每一檔各記一筆
  `question_type = Q3_screened_out`(direction 取輕量評分的傾向、
  分數用輕量分數、thesis_summary 寫淘汰理由、horizon 與入選者相同、
  無交易計畫)。這些紀錄**不計入勝率與方向準確率**,只用於
  calibration_report 的「篩選漏斗對照」——沒有它,永遠無法知道
  漏斗是在選股還是在追高

## Q4 點位分析(「X 的點位怎麼看」)

- 多時框:1w 定方向 → 1d 定結構 →(加密貨幣)4h 定進出場
  對每個時框各跑一次 compute_ta.py
- 輸出**情境樹**,三條路徑都要有觸發條件與對應計畫:
  1. 突破:收上 {壓力位} → 目標 / 追進條件
  2. 回踩:回落 {支撐位} 有守 → 進場區
  3. 跌破:收破 {支撐位} → 觀望 / 反手條件
- prediction-meta 記錄主情境(機率最高者)的方向與價位;horizon_days = 30

## Q5 資產配置(「這是我的配置,怎麼調」)

- **先確認三件事,缺任一項就先問使用者**:
  風險承受度、投資期限、流動性需求
- 分析現有曝險:單一標的集中度(>25% 標紅)、板塊/資產類別相關性、
  股/幣/現金比例
- 輸出「調整前 vs 調整後」對比表,每個動作附理由
- 新增標的需各自做輕量評分(消息+技術)佐證
- prediction-meta:對整體配置記一筆(direction = neutral,
  thesis 寫再平衡邏輯),重大新增標的各記一筆;horizon_days = 90

## Q6 日報(「分析今天的 0050」「今日日報」)

追蹤模式:對已關注的標的做「先驗證前次決策 → 再更新今日觀點」的每日追蹤。
**完整走 SKILL.md Step 1–6,不因每日執行而省略任何步驟**;本節只列差異點。

兩種觸發:

- **單標的日報**:「分析今天的 X」「今天的 X 怎麼看」→ 對 X 跑完整日報
- **總覽日報**:「今日日報」「幫我看今天的持股」(未指名標的)→ 先跑
  `python watchlist.py --analyzed-within 14` 取得關注清單
  (近 14 天內分析過、且仍有未到期預測的標的),逐檔跑單標的日報,
  最後另存一份彙總報告(格式見 report-templates.md「Q6 總覽彙總」)。
  **範圍護欄**:清單 > 8 檔 → 先把清單列給使用者確認要跑哪些
  (全部/近 N 天/指定幾檔),不可默默跑完整流程數十檔;
  Q2/Q3 長 horizon 標的若近期沒再分析,預設不進總覽
  (使用者可用「連舊的一起看」擴大範圍,對應 `watchlist.py` 不帶參數)

流程差異:

1. **前次決策驗證(Step 1.5 歷史回顧之後強制加跑,兩層,不可省略)**:
   - **收盤級正式判定**:跑 `python verify_predictions.py --fetch`,
     引用該標的每筆未到期預測的 status(OPEN/WIN/LOSS/FLAT/NOT_FILLED)
   - **盤中現價對照**:用今日現價逐條對照前次報告的掛單表、SL/TP 與
     失效條件,標註「已觸發 / 接近(距離 ≤ 1×ATR)/ 未觸發」
   - 兩層結果填入「前次決策驗證表」(report-templates.md Q6 區塊),
     每列的「今日決策」欄必答:**掛單保留 / 撤單 / 調整 / 停止追蹤**,
     失效條件已觸發 → 必須撤單,不得改寫成逢低加碼
2. 側重:前收到現價的變化(缺口、量能、籌碼增量)+ 當日新聞;
   時框 1d 為主、1w 確認大方向;WebSearch 至少 1 次為當日盤勢/新聞查詢
2.5. **來源多樣性檢查(不可省略)**:日報最容易退化成「每檔都引用同兩則
   大盤通稿」。存檔前跑 `python cache_news.py --stats --symbol <symbol>`,
   `independent_sources` < 3 → 先補搜尋(ETF 補代理標的、個股補反向查詢
   與外媒),補不到才依 rubric §IV 扣分並在報告明說;
   總覽日報另跑一次不帶 `--symbol` 的 `--stats`,若當日
   `recent_item_count` 為 0(整天沒抓到任何新聞)→ 彙總報告開頭必須註明
   「本日消息面為舊快取,判斷主要由技術面與籌碼面驅動」
3. **首次分析的標的**(recall_history 無紀錄)→ 明說「無前次決策可驗證」,
   其餘依 Q4 點位分析的規格輸出情境樹
4. **預測日誌規則(觀點有變才記,防止日誌灌水)**:
   - **沿用**:方向不變且關鍵點位(進場/SL/TP)調整 < 1×ATR →
     **不記新預測**,報告「與上次觀點的差異」註明
     「沿用 {日期} 觀點,{prediction id} 繼續計時」
   - **改變**:方向翻轉、關鍵點位調整 ≥ 1×ATR、或前次預測已到期/已判定
     (WIN/LOSS/FLAT/NOT_FILLED)→ 記一筆 `question_type = Q6_daily`,
     horizon_days = 30;方向翻轉仍受 Step 1.5 的
     「說不出新事實 → 信心 −10」約束
5. 總覽日報:每檔各存一份完整報告,彙總報告只彙整結論、
   **本身不記預測日誌**

## 通用規則

- 問題橫跨多類(如「能買嗎?順便看點位」)→ 以主要意圖為準,
  次要需求併入報告章節,只記一筆日誌
- **附加區塊觸發**(見 report-templates.md「附加區塊」,跨題型適用):
  - 提及配息/殖利率/除息/存股領息 → 必附「配息數據區塊」
    (近 4 次配息表 + 回顧/前瞻殖利率分列 + 下次除息與最後買進日)
  - 比較 ≥ 2 檔標的(「對比」「A 還是 B」「怎麼分配」)→
    必附「比較表格區塊」,所有數字同一基準日,結論給情境化建議
  - 兩者可同時觸發(如「對比 A B 的配息」→ 比較表格內含配息列
    + 各標的配息數據區塊)
- 使用者未給標的(Q3 與 Q6 總覽日報除外)→ 先問清楚,不猜
- 同標的 1 小時內重複提問 → 沿用剛才的資料與結論(重現性要求:
  方向不得反轉,分數容差 ±10),除非有新的重大消息
